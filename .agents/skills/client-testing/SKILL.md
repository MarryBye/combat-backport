# Client Testing & Verification Workflow

Этот скилл описывает процесс пост-разработки и верификации мода через тестовый клиент.

---

## 📋 Процесс верификации:

1. **Предложение тестирования:**
   - После завершения разработки функционала или внесения правок предложить пользователю запустить тестовый клиент разработки (`./gradlew runClient` или `./gradlew runClient25`).

2. **Запуск и мониторинг логов:**
   - При согласии запустить тестовый клиент в фоновом режиме через `run_command` (например, `./gradlew runClient`).
   - Отслеживать поступающие логи консоли на наличие ошибок, варнингов FML/Mixins и критических исключений (Crash Report / Exception).

3. **Автоматический фикс крашей:**
   - Если в процессе запуска или игры обнаружен краш / ошибка инициализации, немедленно проанализировать стэктрейс, определить причину и приступить к автономному исправлению кода.
   - После фикса повторить запуск для проверки.

4. **Завершение сессии тестирования:**
   - Когда тестовый клиент штатно закрывается пользователем, спросить пользователя:
     *"Тестирование завершено. Все ли прошло хорошо или требуются дополнительные исправления?"*
   - Если пользователь подтверждает, что все работает корректно — задача считается выполненной.
   - Если пользователь сообщает о багах/замечаниях — приступить к их доработке.
